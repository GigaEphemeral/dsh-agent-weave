# 问题 A1：`subagent/end` 事件名错

## 现象

**Host 端日志**（每次节点执行都会出现）：

```json
{"ts":...,"component":"weave-addsubagent","msg":"startContinuable 返回",
 "data":{"childId":"82b9ccc8-...","elapsedMs":48}}

（5 分钟后）

{"ts":...,"component":"weave-addsubagent","msg":"等待 subagent/end 超时，返回空 output",
 "data":{"childId":"82b9ccc8-...","timeoutMs":300000}}

{"ts":...,"component":"weave-addsubagent","msg":"子代理执行返回",
 "data":{"stopReason":"completed","outputBlocks":0,"textLen":0}}
```

**用户视角**：
- 看板节点变绿，但产物 0 行
- 下游节点启动，但拿不到上游产物
- 每个节点固定 5 分钟"完成"（超时时间）

## 根因

`state-graph.ts` 里 `ctx.on('subagent/end', handler)` 订阅的事件名**在 DSH 中不存在**。

- 订阅无效 → 事件永不到达
- 5 分钟超时兜底 → `finish()` 返回空
- 节点被误判为"完成"

## 修复方案

**不猜事件名**。新建一个事件适配层，**多候选订阅**——探测结果出来后可以收敛。

## 代码示例

**新建 `src/l2-engine/subagent-events.ts`**：

```typescript
/**
 * DSH subagent 事件订阅适配层。
 *
 * 屏蔽 DSH 事件名的不确定性——多候选订阅，命中即生效。
 * PR-2 探测完成后可收敛为单一事件名。
 */
import type { Context } from '@deepseek-ai/cordis'

export interface SubagentActivity {
  kind: 'thinking' | 'tool-call' | 'tool-result' | 'assistant'
  tool?: string
  args?: string
  result?: string
  text?: string
}

export interface SubagentEndPayload {
  output: Array<{ type: string; text?: string }>
  stopReason: string
}

export interface SubagentEventHandlers {
  onActivity?: (activity: SubagentActivity) => void
  onEnd?: (payload: SubagentEndPayload) => void
  onError?: (error: Error) => void
}

/** 事件名候选（PR-2 探测后收敛）。 */
const ACTIVITY_EVENTS = [
  'subagent/message',
  'subagent/tool-call',
  'subagent/tool-result',
  'subagent/thinking',
  'session/event',
] as const

const END_EVENTS = ['subagent/end', 'subagent/complete', 'subagent/turn-end'] as const
const ERROR_EVENTS = ['subagent/error', 'subagent/fail'] as const

/** 判断 payload 是否属于指定 childId。 */
function belongsTo(payload: unknown, childId: string): boolean {
  if (!payload || typeof payload !== 'object') return false
  const p = payload as Record<string, unknown>
  return p.id === childId || p.childId === childId || p.subagentId === childId
}

/** 从 payload 提取活动。 */
function extractActivity(payload: unknown): SubagentActivity | null {
  if (!payload || typeof payload !== 'object') return null
  const p = payload as Record<string, unknown>

  if (p.tool || p.toolName) {
    const args = p.args ?? p.arguments ?? p.params
    return {
      kind: 'tool-call',
      tool: String(p.tool ?? p.toolName ?? ''),
      args: typeof args === 'string' ? args : JSON.stringify(args ?? {}).slice(0, 300),
    }
  }
  if (p.toolResult !== undefined || p.result !== undefined) {
    return {
      kind: 'tool-result',
      tool: String(p.tool ?? ''),
      result: JSON.stringify(p.toolResult ?? p.result ?? {}).slice(0, 300),
    }
  }
  if (typeof p.text === 'string') {
    return { kind: 'assistant', text: p.text.slice(0, 300) }
  }
  return null
}

/** 订阅指定 childId 的所有事件。返回 disposer。 */
export function subscribeSubagentEvents(
  ctx: Context,
  childId: string,
  handlers: SubagentEventHandlers,
): () => void {
  const disposers: Array<() => void> = []

  const trySubscribe = (name: string, handler: (payload: unknown) => void) => {
    try {
      const dispose = (ctx as unknown as {
        on(name: string, cb: (payload: unknown) => void): (() => void) | void
      }).on(name, handler)
      if (typeof dispose === 'function') disposers.push(dispose)
    } catch {
      // 事件名不存在，忽略
    }
  }

  // 活动事件
  for (const name of ACTIVITY_EVENTS) {
    trySubscribe(name, (payload) => {
      if (!belongsTo(payload, childId)) return
      const activity = extractActivity(payload)
      if (activity) handlers.onActivity?.(activity)
    })
  }

  // 结束事件
  for (const name of END_EVENTS) {
    trySubscribe(name, (payload) => {
      if (!belongsTo(payload, childId)) return
      const p = payload as Record<string, unknown>
      handlers.onEnd?.({
        output: (p.lastAssistantMessage as Array<{ type: string; text?: string }>) ?? [],
        stopReason: String(p.stopReason ?? 'completed'),
      })
    })
  }

  // 错误事件
  for (const name of ERROR_EVENTS) {
    trySubscribe(name, (payload) => {
      if (!belongsTo(payload, childId)) return
      const p = payload as Record<string, unknown>
      const err = p.error as { message?: string } | undefined
      handlers.onError?.(new Error(err?.message ?? 'subagent error'))
    })
  }

  return () => {
    for (const d of disposers) d()
  }
}
```

✅ **必须探测**（PR-2）。适配层的候选列表需要根据探测结果收敛——事件名错了，仍然无效。

# 问题 A2：超时后未 abort 子代理

## 现象

- 日志里 R1 5 分钟"超时"
- 但 R2 启动后 **R1 仍在跑**
- **R2 累计消耗 3.1M token**（16 分钟）
- 多个节点同时活跃，token 同时燃烧

## 根因

`waitForSubagentEnd` 超时后**只 resolve**，**没有调用任何中止 API**：

```typescript
timer = setTimeout(() => {
  logger.warn(...)
  finish()  // ← 只 resolve，子代理继续在后台跑
}, timeoutMs)
```

## 修复方案

**改用新的等待机制**（见问题 A3）。核心变化：
- 去掉硬超时
- 用户中止时调用 `ctx.subagents.interrupt(childId, authority)` 真正停止子代理
- 底层报错走 `subagent/error` 事件

## 代码示例

**这段代码属于问题 A3 的完整实现**，见问题 A3 的 `subagent-waiter.ts`。

## 是否需要探测

✅ **必须探测**（PR-1）：`interrupt` 的签名和 authority 参数。若 API 不存在，走降级方案。

# 问题 A3：硬超时设计错误

## 现象

- 5 分钟固定超时
- 慢任务（8 分钟的正常任务）被误判为"超时" → 假完成 → 下游启动
- 真卡死的任务反而还在烧 token
- 用户无法区分"慢"和"卡死"

## 根因

**"时间到了 = 失败"的设计假设错误**。5 分钟是任意值，无法区分：
- LLM 在生成超长响应（正常）
- 子代理在跑长 shell 命令（正常）
- 子代理陷入循环（卡死）

三者外表一样：**"一段时间没事件"**。

## 修复方案

**无硬超时**。引擎**不做超时判断**——让底层处理：

| 层 | 谁负责超时 | 我们能看到什么 |
|---|---|---|
| LLM API | 平台 | `subagent/error` 事件 |
| 网络 | OS socket | 连接断开 |
| DSH 框架 | DSH | `subagent/error` 事件 |
| **图引擎** | **不做超时** | 只等 `end` / `error` / 用户 abort |

**只有三种退出路径**：
1. `subagent/end` → resolve（正常完成）
2. `subagent/error` → reject（底层报错）
3. `signal.abort()` → reject(`PauseError`)（用户暂停）

**空闲只提示，不中止**（见问题 D3）。

## 代码示例

**新建 `src/l2-engine/subagent-waiter.ts`**：

```typescript
/**
 * 子代理等待器（超时重设计）。
 *
 * 核心原则：无硬超时。只响应三种信号：
 *   1. subagent/end    → resolve
 *   2. subagent/error  → reject
 *   3. signal.abort()  → reject(PauseError)
 *
 * 空闲/循环只提示，不中止。
 */
import type { Context } from '@deepseek-ai/cordis'
import {
  subscribeSubagentEvents,
  interruptSubagent,
  type SubagentActivity,
  type SubagentEndPayload,
} from './subagent-events.js'
import { logger } from '../shared/logger.js'

/** 用户主动暂停信号。 */
export class PauseError extends Error {
  constructor(public readonly childId: string) {
    super(`用户暂停：${childId}`)
    this.name = 'PauseError'
  }
}

export interface WaitOptions {
  /** 空闲提示阈值（毫秒，0 = 不提示；默认 10 分钟） */
  idleWarningMs?: number
  onIdleWarning?: (idleMs: number) => void
  /** 循环检测配置（默认开启） */
  loopDetection?: {
    enabled: boolean
    window: number
    repeatThreshold: number
  }
  onLoopDetected?: (tool: string, repeatCount: number) => void
  onActivity?: (activity: SubagentActivity) => void
  /** 用户中止信号 */
  signal?: AbortSignal
  /** 父 Agent（用于 interrupt authority） */
  parentAgent?: unknown
}

export function waitForSubagentEnd(
  ctx: Context,
  childId: string,
  opts: WaitOptions = {},
): Promise<SubagentEndPayload> {
  return new Promise((resolve, reject) => {
    let lastActivityAt = Date.now()
    let idleWarningFired = false
    let idleCheckTimer: NodeJS.Timeout | null = null
    const recentCalls: Array<{ key: string; at: number }> = []
    let loopDetected = false

    // ─── 空闲检查（只提示） ───
    function scheduleIdleCheck() {
      const threshold = opts.idleWarningMs ?? 600_000
      if (!threshold) return
      idleCheckTimer = setInterval(() => {
        const idleMs = Date.now() - lastActivityAt
        if (idleMs >= threshold && !idleWarningFired) {
          idleWarningFired = true
          logger.warn('weave-addsubagent', '子代理长时间无活动（仅提示，不中止）', {
            childId,
            idleMs,
          })
          opts.onIdleWarning?.(idleMs)
        }
      }, 30_000)
    }

    // ─── 活动处理 ───
    function handleActivity(activity: SubagentActivity) {
      lastActivityAt = Date.now()
      idleWarningFired = false

      if (opts.loopDetection?.enabled && activity.kind === 'tool-call') {
        const key = `${activity.tool}:${activity.args ?? ''}`
        recentCalls.push({ key, at: Date.now() })
        const window = opts.loopDetection.window
        if (recentCalls.length > window) recentCalls.shift()

        const counts = new Map<string, number>()
        for (const c of recentCalls) counts.set(c.key, (counts.get(c.key) ?? 0) + 1)
        const maxRepeat = Math.max(...counts.values(), 0)

        if (maxRepeat >= opts.loopDetection.repeatThreshold && !loopDetected) {
          loopDetected = true
          logger.warn('weave-addsubagent', '检测到循环调用（仅提示）', {
            childId,
            tool: activity.tool,
            repeatCount: maxRepeat,
          })
          opts.onLoopDetected?.(activity.tool ?? '', maxRepeat)
        }
      }

      opts.onActivity?.(activity)
    }

    // ─── 订阅事件 ───
    const dispose = subscribeSubagentEvents(ctx, childId, {
      onActivity: handleActivity,
      onEnd: (payload) => {
        cleanup()
        resolve(payload)
      },
      onError: (error) => {
        cleanup()
        reject(error)
      },
    })

    // ─── 用户中止 ───
    opts.signal?.addEventListener('abort', async () => {
      logger.info('weave-addsubagent', '收到用户中止信号', { childId })
      try {
        await interruptSubagent(ctx, childId, opts.parentAgent)
        logger.info('weave-addsubagent', '已发送 interrupt 请求', { childId })
      } catch (err) {
        logger.warn('weave-addsubagent', 'interrupt 调用失败', {
          childId,
          error: err instanceof Error ? err.message : String(err),
        })
      }
      cleanup()
      reject(new PauseError(childId))
    }, { once: true })

    function cleanup() {
      if (idleCheckTimer) clearInterval(idleCheckTimer)
      dispose()
    }

    scheduleIdleCheck()
  })
}
```

**改造 `state-graph.ts` 的 `addSubagent`** 使用新 waiter（完整代码见问题 A5 末尾）。

✅ **必须探测**（PR-2）：事件名。`waitForSubagentEnd` 依赖 `subscribeSubagentEvents`，事件名错了还是无效。

# 问题 A4 + A5：暂停未用 interrupt / 缺 authority

## 现象

- 用户点"暂停"，图不暂停
- 或：调用 `interrupt` 时抛错 `cannot get property "off" without inject` / `interrupt` 无效

## 根因

**两层问题**：

**A4**：旧代码里 `waitForSubagentEnd` 超时用 `ctx.off` 清理订阅 → `ctx.off` 未 inject → 报错 → 崩溃。

**A5**：即使改用 disposer，暂停时也没调用 DSH 原生 `interrupt`——只是 resolve 了 Promise，**子代理继续跑**。

## 修复方案

**用 DSH 原生 `interrupt(childId, authority)`**：

- 签名：`ctx.subagents.interrupt(targetSessionId, authority)`
- **必须传 `authority`**：`{ kind: 'ancestor', agent: parentAgent }`
- `authority.kind` 有两种：
  - `'user'` + `parentSessionId` — 用户通过 Web UI 停
  - `'ancestor'` + `agent` — 父 Agent 主动停

**我们场景**：父 Agent（图引擎持有的 `nodeCtx.agent`）停下级。

**同时**：用 `ctx.on()` 返回的 **disposer** 清理订阅，不用 `ctx.off`。

## 代码示例

**在 `subagent-events.ts` 加 `interruptSubagent`**：

```typescript
// src/l2-engine/subagent-events.ts

/**
 * 停止子代理当前轮次（DSH 原生 interrupt）。
 *
 * ctx.subagents.interrupt(targetSessionId, authority)
 * authority: { kind: 'ancestor', agent } — 调用者必须是目标的活跃祖先 Agent。
 */
export async function interruptSubagent(
  ctx: Context,
  childId: string,
  parentAgent: unknown,
): Promise<void> {
  const subagents = ctx.subagents as unknown as {
    interrupt?: (targetSessionId: string, authority: unknown) => void
  }
  if (typeof subagents.interrupt !== 'function') {
    throw new Error('ctx.subagents.interrupt 不可用（PR-1 探测确认）')
  }
  subagents.interrupt(childId, { kind: 'ancestor', agent: parentAgent })
}
```

**在 `waitForSubagentEnd` 里调用**（已包含在问题 A3 的代码里）：

```typescript
opts.signal?.addEventListener('abort', async () => {
  try {
    await interruptSubagent(ctx, childId, opts.parentAgent)
  } catch (err) {
    logger.warn('weave-addsubagent', 'interrupt 调用失败', { childId, error: ... })
  }
  cleanup()
  reject(new PauseError(childId))
}, { once: true })
```

**在 `addSubagent` 调用 waiter 时传 parentAgent**：

```typescript
result = await waitForSubagentEnd(nodeCtx.ctx, started.childId, {
  // ... 其他配置
  signal,
  parentAgent: agent,  // ← 关键：传父 Agent 作 authority
})
```

## 是否需要探测

✅ **必须探测**（PR-1）：

- `interrupt` 是否存在
- authority 参数的联合类型是否真的是 `{ kind: 'ancestor', agent }`

**如果探测失败（`interrupt` 不存在）→ 降级方案**：

```
1. 图控制层暂停（graphControl.pause() 生效，后续节点不启动）
2. 当前节点等待自然结束（不 abort）
3. 前端提示："当前节点仍在运行，将等待其完成后暂停；如需立即中止，请使用 DSH 原生 Stop 按钮"
4. 子代理结束后 → 图停在节点边界
```

**降级方案的代码**：

```typescript
opts.signal?.addEventListener('abort', () => {
  logger.info('weave-addsubagent', '用户中止信号收到，interrupt 不可用，等待自然结束', { childId })
  // 不 reject，让 waitForSubagentEnd 继续等 subagent/end
  // 图控制层负责暂停后续节点启动
}, { once: true })
```

# 问题 B1：图暂停前端不可见

## 现象

- Host 端日志：`{"msg":"图暂停（需人工介入）","pauseReason":"tool-error-fatal"}`
- **前端看板无任何变化**
- 用户不知道图已暂停

## 根因

**事件链四层中某层断了**。可能：

- L1：`state-graph.ts` 的 catch 块没有 emit `graph/paused`（只打 logger）
- L2：`TrajectoryEvent` 类型没定义 `'graph/paused'`
- L3：`WsEventSchema` 的 enum 没加 `'graph-paused'`
- L4：`useGraphStream` 没处理 `'graph-paused'` 分支

## 修复方案

**四层全部补齐**。

## 代码示例

**L1：`state-graph.ts` 的 catch 块**：

```typescript
} catch (error) {
  // ★ 用户暂停 → 图暂停（不是失败）
  if (error instanceof PauseError) {
    emit({
      type: 'graph/paused',
      graphId,
      node: current,
      timestamp: Date.now(),
      data: {
        reason: 'user-pause',
        childId: error.childId,
        resumeFrom: current,
      },
    })
    return {
      graphId, success: true, finalState: state, trajectory, iterations: iteration,
      data: { paused: true, reason: 'user-pause', resumeFrom: current },
    }
  }

  // 其他错误
  emit({
    type: 'graph/node-error',
    graphId, node: current, timestamp: Date.now(),
    data: { error: error instanceof Error ? error.message : String(error) },
  })
  return { graphId, success: false, finalState: state, trajectory, iterations: iteration, error }
}
```

**L2：`types.ts` 的 `TrajectoryEvent`**：


# 问题 C1：capability 未生效（R2 spawn 下级）

## 现象

- R2 一个节点烧 **3.1M token**（16 分钟）
- 看板显示 R2 内部有多个子代理活动
- 角色 YAML 里写了 `capability.allow_delegation: false`，但没生效

## 根因

`role-loader.ts` 的 `compileRoleToProvider` **没读 capability**：

```typescript

  ...request,
  toolFilter: { allow: [...profile.toolFilter] },  // ← 直接用 tools 字段
  // 没有从 capability.allow_delegation 剥离 spawn 类工具
  // 没有从 capability.max_depth 读 maxDepth
}
```

**叠加**：`subagent` 工具是 DSH 内置能力，**不走 `toolFilter`**。需要显式声明禁止。

## 修复方案

**三层防护**：

1. **工具白名单剥离**：`toolFilter.allow` 过滤掉 spawn 类工具
2. **maxDepth 从 capability 读**：从 `max_concurrent_children` 改为 `capability.max_depth`
3. **尝试 `allowSubagents: false`**：DSH 若支持则生效（探测 PR-3 确认）

## 代码示例

**改 `src/l3-roles/role-loader.ts`**：

```typescript
/** 禁止 spawn 的工具名单。 */
const FORBIDDEN_TOOLS = new Set(['subagent', 'delegate', 'spawn', 'fork', 'create_child'])

function sanitizeTools(tools: string[], capability: RoleCapability | undefined): string[] {
  if (capability?.allow_delegation === false) {
    return tools.filter((t) => !FORBIDDEN_TOOLS.has(t.toLowerCase()))
  }
  return tools
}

export function compileRoleToProvider(role, options, delegate) {
  const profile = compileRoleProfile(role, options)

  return {
    name: profile.name,
    capabilities: { /* ... 现有 */ },
    inheritsParentContext: profile.inheritsParentContext,
    agentRouteDefaults: profile.agentOptions,

      const injected = {
        ...request,
        persona: profile.persona,
        // ★ 剥离 spawn 类工具

        agentOptions: { ...profile.agentOptions },
        // ★ maxDepth 从 capability 读
        maxDepth: role.capability?.max_depth ?? 0,
        // ★ 尝试禁用子代理（DSH 支持则生效）
        ...(role.capability?.allow_delegation === false
          ? { allowSubagents: false } as never
          : {}),
      }
      return delegate.start(injected)
    },
  }
}
```

# 问题 D1：输入门禁未启用

## 现象

- R4 在 prompt 里说"上游产物为空"

```typescript

nodes.set(name, async (state, nodeCtx, signal) => {
```

# 问题 D2：循环检测未实现

## 现象

- 子代理反复调用同一工具，无法识别
- 用户等到超时才反应过来

## 根因

**未实现**。

## 修复方案

**在 `subagent-waiter.ts` 的 `handleActivity` 里加**：

- 记录最近 N 次工具调用
- 相同工具+参数出现 ≥ 阈值次 → emit `graph/node-loop-detected`
- **只提示，不中止**（用户决定）

## 代码示例

**已包含在问题 A3 的 `subagent-waiter.ts` 里**：

```typescript
function handleActivity(activity: SubagentActivity) {
  lastActivityAt = Date.now()
  idleWarningFired = false

  if (opts.loopDetection?.enabled && activity.kind === 'tool-call') {
    const key = `${activity.tool}:${activity.args ?? ''}`
    recentCalls.push({ key, at: Date.now() })
    const window = opts.loopDetection.window
    if (recentCalls.length > window) recentCalls.shift()

    const counts = new Map<string, number>()
    for (const c of recentCalls) counts.set(c.key, (counts.get(c.key) ?? 0) + 1)
    const maxRepeat = Math.max(...counts.values(), 0)

    if (maxRepeat >= opts.loopDetection.repeatThreshold && !loopDetected) {
      loopDetected = true
      logger.warn('weave-addsubagent', '检测到循环调用（仅提示）', {
        childId, tool: activity.tool, repeatCount: maxRepeat,
      })
      opts.onLoopDetected?.(activity.tool ?? '', maxRepeat)
    }
  }

  opts.onActivity?.(activity)
}
```

**默认配置**：`{ enabled: true, window: 10, repeatThreshold: 5 }`

```typescript
function scheduleIdleCheck() {
  const threshold = opts.idleWarningMs ?? 600_000
  if (!threshold) return
  idleCheckTimer = setInterval(() => {
    const idleMs = Date.now() - lastActivityAt
    if (idleMs >= threshold && !idleWarningFired) {
      idleWarningFired = true
      logger.warn('weave-addsubagent', '子代理长时间无活动（仅提示，不中止）', {
        childId, idleMs,
      })
      opts.onIdleWarning?.(idleMs)
    }
  }, 30_000)
}
```

```typescript
case 'node-idle-warning':
```
