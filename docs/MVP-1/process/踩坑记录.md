# MVP-1 踩坑记录（可检索知识条目）

> 版本：v1（2026-09-22）｜用途：后续 MVP 复用；每条含「症状 → 根因 → 解决」
> 标注：🔴 阻断级 / 🟡 干扰级 / 🟢 提示级

## 坑 1 🔴 工具名含冒号被真实 LLM 端点拒绝

| 项 | 内容 |
|---|---|
| **症状** | 真实 LLM 发消息报 `400 InvalidParameter: tools.23.function.name: expected 1-128 ASCII letters, digits, underscores or hyphens` |
| **根因** | 工具名 `weave:run-chain` 含**冒号**；OpenAI 兼容端点的函数名规范为 `^[a-zA-Z0-9_-]{1,128}$`。DSH 内部工具表允许冒号，但转成 provider 请求时被拒 |
| **为何 mock 没暴露** | `llm-mock-server` 不校验函数名（只校验路径/token/JSON），故 mock 端到端全绿而真实环境直接 400 |
| **解决** | 工具名改为 `weave_run_chain`（下划线，符合 DSH 官方惯例：`send_message`/`run_code`/`todo_write`） |
| **教训** | **mock 验证通过 ≠ 真实环境通过**。凡是「传给模型 provider 的字段」都要按 provider 规范校验（工具名、schema 形状、消息角色等） |

## 坑 2 🔴 角色模型必须用模型 ID（非 name）

| 项 | 内容 |
|---|---|
| **症状** | 子代理全部 `stop_reason: error`，session 内 `UNKNOWN_MODEL: pi-ai provider "huoshan-186" has no configured model "deepseek-v4-flash"` |
| **根因** | `llm-pi-ai` 用 settings 里的 **`id`**（`DeepSeek-V4-Flash`）做模型解析键，不是 `name`（`deepseek-v4-flash`） |
| **解决** | 角色 YAML 的 `model.model` 与 `agent-default-model.model` 都写 ID：`DeepSeek-V4-Flash` |
| **教训** | settings 的 `models[].id` 是路由键；`name` 只是显示名 |

## 坑 3 🔴 bundle 声明格式错误导致插件不挂载

| 项 | 内容 |
|---|---|
| **症状** | 安装后 `dsh: warning: dsh-agent-weave declares no dsh.bundle — installed as a plain dependency, not a profile layer` |
| **根因** | 写成 `"dsh": { "bundle": "./lib/index.js" }`（字符串）；官方契约是**对象**：`{ bundle: { patch: "./cordis.patch.yml" } }`（`exportsPatch` 读 `dsh.bundle.patch`） |
| **解决** | `"dsh": { "bundle": { "patch": "./cordis.patch.yml" }, "client": { "platform": "web" } }` |
| **附带** | `dsh.client` 也必须是对象（`{platform}`），否则 boot 报 `non-object dsh.client declaration` |

## 坑 4 🔴 package.json files 未含整个 lib 导致 boot 失败

| 项 | 内容 |
|---|---|
| **症状** | boot 报 `Cannot find module .../lib/l3-roles/role-loader.js` |
| **根因** | `files` 只列了 `lib/index.js`，子目录模块（`lib/l3-roles/`、`lib/l2-engine/`、`lib/shared/`）未打包 |
| **解决** | `files` 写 `"lib"`（整目录）+ `cordis.patch.yml` + `roles` + `skills` |

## 坑 5 🔴 路径解析不能依赖 process.cwd()

| 项 | 内容 |
|---|---|
| **症状** | boot 报 `角色目录读取失败: D:\...\roles: ENOENT`（解析到 DSH 启动目录而非插件目录） |
| **根因** | `rolesDir` 默认用 `process.cwd()`；DSH 启动目录 ≠ 插件包目录 |
| **解决** | 用 `import.meta.url` 定位插件包根：`resolve(dirname(fileURLToPath(import.meta.url)), '..')` |

## 坑 6 🟡 pnpm 12 (Windows) 符号链接目标失效

| 项 | 内容 |
|---|---|
| **症状** | `node --input-type=module -e "import('@deepseek-ai/dsh-tools')"` 报 `ERR_MODULE_NOT_FOUND`；链接目标 `node_modules/.pnpm/@deepseek-ai+x@0.1.5-rc.2/` 不存在 |
| **根因** | pnpm 12 在 Windows 上创建链接指向 `@deepseek-ai+x@<ver>`，实际 store 目录是哈希名 `@deepseek-ai+x@0.1._<hash>` |
| **解决** | 跑 `test-env/fix-pnpm-links.mjs`（重建为 junction 指向真实哈希目录）；创建符号链接需管理员权限，用 junction 免提权 |
| **注意** | 顶层 `node_modules/@deepseek-ai/<pkg>` 是 SymbolicLink 时会失效；改用 Junction |

## 坑 7 🟡 PowerShell 内置变量 `$home` 只读

| 项 | 内容 |
|---|---|
| **症状** | 设 `$home = '<隔离目录>'` 报 `Cannot overwrite variable HOME because it is read-only`，导致 `$env:DSH_HOME` 被误设为 `C:\Users\<user>`，意外在用户主目录创建 `profiles/` |
| **根因** | `$HOME` 是 PowerShell 内置只读变量（大小写不敏感） |
| **解决** | 用 `$dshHome` 等非保留名；已清理误建目录 `C:\Users\<user>\profiles` |

## 坑 8 🟡 真实 LLM 单阶段耗时 3-15 分钟（非卡死）

| 项 | 内容 |
|---|---|
| **症状** | 某角色 session 数分钟不落盘，疑似 hang |
| **根因** | DSH 在 turn 完成后才落盘 session；模型生成大文档（如 R4 详细设计 26KB）期间 session 大小不变，但进程 CPU 持续增长 |
| **判别方法** | 看进程 CPU 是否持续增长（增长 = 活跃生成）+ session 最后事件是否为 `step/start`（未到 `turn/end`） |
| **实测耗时** | R1 ~2.5min、R2 ~5min、R4 ~15min（长文档） |
| **教训** | 不要用「session 大小不变」判定卡死；用 CPU + 事件流判定 |

## 坑 9 🟢 PowerShell 控制台中文乱码 ≠ 文件编码错误

| 项 | 内容 |
|---|---|
| **症状** | 读产物文件显示乱码，疑似写入编码错误 |
| **根因** | Windows PowerShell 控制台默认 GBK 显示 UTF-8 文件 |
| **判别** | 读原始字节：`E3 80 90` = `【` 的 UTF-8 编码 → 文件本身正确 |
| **解决** | `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8`；或 `[System.IO.File]::ReadAllText($p, [Text.Encoding]::UTF8)` |
