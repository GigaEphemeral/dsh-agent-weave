

## 六、SKILL 系列：Skill 优化（10 个任务）

### 为什么需要独立的 SKILL 系列

MVP-1 暴露的核心问题不是"角色能不能跑通"，而是"**角色跑通的方式不对**"：

| 现象 | 本质 |
|---|---|
| 井字棋任务下 R2 产出 8.8KB 架构文档、R4 产出 16.9KB 详细设计 | 角色 Skill 的**任务类型假设**与轻量任务不匹配 |
| R6 反复勘察 TS 工具链、5+ 步无产出 | Prompt 硬编码技术栈 + 工具权限过宽 |
| R6 产出 `README.md` 而非可运行文件 | 输出格式契约未约定 |
| 六阶段全跑完但产品是"过度工程" | 缺乏**任务类型 → 角色集/深度**的裁剪机制 |

### SKILL.1 角色 Skill 现状审计（P0）

| 项 | 内容 |
|---|---|
| **目标** | 盘点 R1-R8 现有 Skill 的职责假设、输出格式、工具依赖、任务类型倾向 |
| **交付物** | `docs/MVP-1/skill-audit.md` |
| **审计维度** | ① 核心能力（不变的部分）② 任务类型假设 ③ 输出格式契约 ④ 工具依赖 ⑤ 质量门标准 |
| **预估** | 1d｜**阻塞 MVP-2**：✅ 是 |

### SKILL.2 核心能力与任务适配层分离（P0）

| 项 | 内容 |
|---|---|
| **目标** | 将每个 Skill 重构为"核心能力层 + 任务类型适配层" |
| **交付物** | 重构后的 `skills/<role>/` 目录（含 `CORE.md` + `adapters/*.md`） |
| **设计示例** | R4 设计师：<br>· `CORE.md` — 详细设计方法论<br>· `adapters/lightweight.md` — 轻量任务：单文件、跳过 UML<br>· `adapters/standard.md` — 标准任务：完整设计文档<br>· `adapters/enterprise.md` — 企业级：含 DDD 建模 |
| **预估** | 3d｜**阻塞 MVP-2**：✅ 是 |

### SKILL.3 任务类型识别机制（P1）

| 项 | 内容 |
|---|---|
| **目标** | 在链启动前，根据用户需求自动识别任务类型，选择对应的适配层 |
| **交付物** | `src/l2-engine/task-classifier.ts` |
| **设计要点** | ① 用轻量 LLM 调用或规则判断任务类型<br>② 分类维度：规模、领域、复杂度<br>③ 输出：任务类型标签 + 建议角色集 + 建议适配层 |
| **预估** | 1.5d｜**阻塞 MVP-2**：⚠️ 影响角色选择设计 |

### SKILL.4 Prompt 模板中性化（P0）

| 项 | 内容 |
|---|---|
| **目标** | 移除所有 Prompt 中硬编码的技术栈，改为"按上游设计的技术选型" |
| **交付物** | 修订后的 `src/l2-engine/mvp1-chain.ts` + 各 Skill 的 Prompt 模板 |
| **设计要点** | ① 搜索所有 Prompt 中的技术栈关键词<br>② 替换为中性表述<br>③ 增加硬性约束段："禁止探索环境/禁止跑命令/单轮完成" |
| **预估** | 1d｜**阻塞 MVP-2**：✅ 是 |

### SKILL.5 工具权限分层（P0）

| 项 | 内容 |
|---|---|
| **目标** | 按角色职责定义最小工具集 |
| **交付物** | 修订后的 `roles/*.yaml` 的 `tools` 字段 + `docs/MVP-1/tool-permissions.md` |
| **设计要点** | ① R1 零工具 ② R2/R4/R6/R7/R8 仅 `read` ③ R6 加 `write`（限定 `productions/<角色ID>/`）④ 明确禁止 `pwsh` / `glob` / `grep` |
| **预估** | 0.5d｜**阻塞 MVP-2**：✅ 是 |

### SKILL.6 质量门标准量化（P1）

| 项 | 内容 |
|---|---|
| **目标** | 将每个角色的 `quality_gate` 从模糊描述改为可量化标准 |
| **交付物** | 修订后的 `roles/*.yaml` 的 `quality_gate` 字段 |
| **设计示例** | R1 → "PRD 含用户故事 + 验收标准 + 不做清单"；R6 → "产出文件可运行 + 无 TODO + 无占位符" |
| **预估** | 1d｜**阻塞 MVP-2**：⚠️ 影响质量门设计 |

### SKILL.7 输出格式契约化（P1）

| 项 | 内容 |
|---|---|
| **目标** | 为每个角色定义明确的输出格式契约 |
| **交付物** | `docs/MVP-1/output-contracts.md` + 各 Skill 的输出格式段 |
| **设计要点** | ① R1/R2/R4/R7/R8 输出 Markdown<br>② R6 输出**可运行代码文件**，禁止输出说明文档<br>③ 所有角色产出落盘到 `productions/<角色ID>/` |
| **预估** | 0.5d｜**阻塞 MVP-2**：✅ 是 |

|---|---|
