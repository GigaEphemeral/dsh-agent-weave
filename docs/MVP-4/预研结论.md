## PR-M4.1 + PR-M4.5：Slots 挂载点探测（D1+D3 重点）

**来源**：`@deepseek-ai/dsh-client-ui-conversation/lib/types/client/contract/slots.d.ts` + `views.d.ts` + `dsh-client-ui-workflow-run/lib/client.js`（官方实现参考）。

### 关键结论

| 计划写法 | 实际契约 | 处置 |
|---|---|---|
| `ctx.slots.inject('conversation.header', ...)` | **不存在** `conversation.header` | ❌ 改用 `conversation.session.header.actions` |
| `ctx.slots.inject('conversation.view', ...)` | `conversation.view`：`kind:'list'`，`scope:'session'` | ✅ 存在，但需注册 ViewTab |
| `ctx.slots.inject(slot, () => <Comp/>)` | `ctx.slots.inject(name, () => ctx.slots.register({name, id/key, label, inject}, Comp))` | ✅ inject 包 register |

### D1 按钮（页头）

```typescript
ctx.slots.inject('conversation.session.header.actions', () =>
  ctx.slots.register({
    name: 'conversation.session.header.actions',
    id: 'weave-dashboard-toggle',
    label: () => 'Weave 看板',
    order: 0,
  }, WeaveDashboardButton),
)
```

- owner props：`{ children?: never }`——按钮状态走模块级 store（dashboard-state.ts），不依赖 owner。
- `kind:'list'` 支持 `order`/`label`。

### D3 主区切换（conversation.view）

```typescript
ctx.slots.inject('conversation.view', () =>
  ctx.slots.register({
    name: 'conversation.view',
    id: 'weave-dashboard',
    label: () => 'Weave 看板',
    order: 10,
  }, WeaveDashboardView),
)
```

- owner props：`ConvViewOwnerProps { viewRequest, openView, completeViewRequest }`。
- View 常驻注册，非 open 时返回 null（切换由 conversation 自身 ViewTab 机制管理）。
- `ConversationStoreState.view: string | null` 持久化用户选择；Chat 是内置 view。

### 注册 API 形态（官方 workflow-run 实证）

```typescript
export const inject = ['uiConversation', 'slots', 'sessions', 'locale'] // 最少 ['slots']
export function apply(ctx: ClientContext): void {
  ctx.slots.inject('conversation.chat.node', () => ctx.slots.register({...}, Component))
}
```

- 组件必须接收 composed props（标准 kit + owner），无 owner 时只收标准 props。
- `ctx.slots.inject` 内部处理 slots 服务就绪时序——**无需手动轮询**。

## PR-M4.2：webServer / SSE / 鉴权探测

**来源**：`@deepseek-ai/dsh-host-webserver/lib/types/index.d.ts` + gateway 使用实证 + 本仓库 MVP-2 reference。

### 关键结论

| 项 | 结论 |
|---|---|
| 服务获取 | `ctx.get('webServer')` 鸭子类型（**不能 inject**：headless/TUI 无此服务会挂起等待） |
| 注册 API | `register({ kind: 'exact'\|'prefix', path, handler(req,res) })`——**对象形式，非字符串路由** |
| 路由参数 | 无 `req.params`——路径参数需 `kind:'prefix'` + 手动解析 pathname |
| SSE | handler 可持有 response（`res.write` 流式），满足 SSE 场景 |
| 重复注册 | 同 (kind,path) 重复抛错（组合级契约） |
| 时序 | webServer 激活即监听；路由注册不影响请求匹配（fallback 404 直到注册） |
| 鉴权 | 无内置 token 机制——MVP-4 用 `x-weave-token` header 与 `WEAVE_API_TOKEN` env 比对（P4.B.9） |

### 等待时序（MVP-2 reference 模式）

```typescript
const webServer = ctx.get('webServer') as { register(r: unknown): unknown } | undefined
// 轮询 5s（25×200ms），headless 静默跳过；ctx.on('dispose') 停止等待
```

## PR-M4.3：React Flow 版本兼容

- 计划 `@xyflow/react ^12` + dagre。Client 构建走 `tsconfig.client.json`（jsx react-jsx，bundler resolution）。
- **决策**：MVP-4 看板渲染用原生 SVG 自绘图（节点≤50 时零新依赖），**不引入 @xyflow/dagre**（P2-10 依赖门禁：peerDeps 新增需供应链审查；自绘更轻）。GraphCanvas 内部实现 SVG 节点/边，预留 React Flow 演进（MVP-5）。

## PR-M4.4：OTEL 事件契约

- 事件字段对齐：`trace_id=graphId` / `span_id=node` / `gen_ai.agent.name=role` / `gen_ai.operation.name` / `gen_ai.usage.*`。Phase A 落 `event-schema.ts`（P4.A.1）+ 单测（P4.A.5）。

## PR-M4.6：大图渲染性能

- 决策：P4.C.2 原生 SVG 渲染 + `onlyRenderVisibleElements` 语义（仅渲染视口内节点，50 节点上限）。50/100/200 基线在 Phase C 后实测。

## PR-M4.7：多图策略

- 决策：**单图模式**（P4.0.16 已定）——`shared-bus.ts` 只维护一个活跃 bus；运行历史另存 `run-history.ts`（Phase B）。
