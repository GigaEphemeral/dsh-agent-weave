## 一、最终目标（一句话）

> **实现一个可视化的 agent 任务编排工具，把任务拆分到一个任务工作流中，多角色 subagent 按工作流自动协作，流水线/团队激活状态全程可视化，每个 agent 独立记忆、可互相对话，高质量交付；角色可由用户导入文件创建，并用画图方式连接角色间交互逻辑。**

6 条硬需求（G）：

| # | 需求 | 一句话验收 |
|---|---|---|
| G1 | 任务拆分 + 工作流 | 一句话需求 → 拆成工作流任务图，角色按图协作 |
| G2 | 非线性/循环编排 | 顺序 + 条件 + 循环（开发→测试→审核循环） |
| G3 | 可视化激活状态 | 谁在跑/等谁/产出啥，实时可见，可恢复 |
| G4 | 记忆纯洁性 | 每 agent 独立记忆，只经文件/消息交接，防污染 |
| G5 | agent 间对话 | subagent 定向对话推进交付 |
| G6 | 角色可自定义 | 导入文件创建角色 + 画图连线交互逻辑 |

## 二、本质定位

> 本工具 = **工作流图编排运行时**。`subagent` 是执行器（DSH 原生，天然独立记忆）；自建 **图 DSL + StateGraph 编排引擎 + 角色管理（YAML）+ 可视化画布 + 可观测治理**。

**卡点归因**（"效果一般"）：现在是**人肉/线性编排**。缺三样质变件：①显式**图 DSL** ②自动**调度运行时**③**状态机 + 可视化**。

## 三、核心对象模型（6 对象）

| 对象 | 定义 | 落点 |
|---|---|---|
| **Agent（角色）** | 特质 + 工具 + 模型 + 质量门/预算 | R1-R10 skill（Prompt 内容）+ YAML 元数据 |
| **Workflow（图）** | 节点=角色/任务，边=顺序/条件/循环/并行 | 图 DSL（JSON，`docs/04` §4.1） |
| **Task（任务实例）** | 一句话 → 根任务 → 子任务树 | 任务树（storageDomain） |
| **State（共享状态）** | Phase/active_agent/artifacts/质量门/retry 计数 | DevTeamState（`docs/04` §3.1） |
| **Memory（角色记忆）** | 每 agent 独立 context + 交接物 | 独立 subagent session + 工作区文件 |
| **RunLedger（运行账本）** | 每次执行的不可变记录：节点级事件流 + Token 分账 + 合规状态 + 人工介入 | storageDomain（与 State 分离，只追加） |

> State 是**当前快照**（可被节点改），RunLedger 是**历史轨迹**（只追加）——后者支撑 MVP-3 可恢复/可追溯、MVP-4 节点染色/Token 可视化。
> RunLedger 默认记录**协作效率度量**（无需额外开发，事件流带 `timestamp/token_usage/outcome` 字段即可，MVP-4 展示）：**首次通过率 ｜ 每任务迭代循环数 ｜ token÷成功交付 ｜ 人工介入率 ｜ 决策延迟**。

## 四、分层架构（L0–L5）

| 层 | 职责 | 复用 / 自建 |
|---|---|---|
| L0 角色资产 | R1-R10 skill + 3 横切纪律 | ✅ 已完成，`system_prompt_ref` 直指 |
| L1 执行与记忆 | Continuable child + 独立 Session + 记忆隔离 | 复用官方 `dsh-subagent` |
| L2 编排引擎 | 图 DSL + 条件边 + 循环回退 + 熔断 + checkpoint | 自建 StateGraph |
| L3 角色管理 | YAML 特质/工具/模型/质量门/预算/handoff/生命周期 | 自建 |
| L4 可视化 | 画布 + 实时激活状态 + Token 监控 | 自建 |
| L5 可观测性与治理 | 执行轨迹追踪 · 审计账本(RunLedger) · 策略合规检查 · 成本熔断 · 行为漂移检测 | 自建（参考 OpenTelemetry 语义 + COSTAR Action Ledger） |

- 复用层仅 L1；自建 L2/L3/L4/L5。L5 依托 DSH 内置 `list_agents`/`send_message`/`interrupt_agent` 能力向上构建，非从零。
- **L5 三大支柱**：**Traces**（每节点输入/输出/耗时/token，`trace_id` 贯穿全链）+ **Metrics**（任务成功率/首次通过率/迭代循环数/决策延迟）+ **Audit Logs**（谁在何时对何节点做了何决策，用于合规验证与复盘）。💡 L5 是 MVP-4 的前提：无 RunLedger 节点级事件流，画布无法染色；无分账，无法识别成本瓶颈。

## 五、三条命门

### 5.1 记忆纯洁性（G4）—— 不共享 context，只经文件+消息交接
- subagent 独立 session 天然隔离；`inheritsParentContext=false`（fresh）是记忆纯洁开关。
- 交接双通道：**产出物=文件（durable）** + **即时协商=消息（transient，`sendMessage`）**。
- 📘 行业印证：Claude Code subagents「每个 subagent 以全新隔离 context window 启动 + 文件交接」；MetaGPT「结构化文档交接 > 自由对话防失真」。

### 5.2 角色间对话（G5）—— 定向 handoff，非广播
- 父代理（编排器）中转让路由；`sendMessage` 定向；防死锁（correlation_id + deadline）。
- 区别：流水线交接（文件为主） vs 即时协商（消息为主）。

### 5.3 可视化激活状态（G3）—— 状态机 + Event 广播
- Host 维护节点状态 `idle/pending/running/waiting/done/error`，Event 广播，Client 画布实时染色。
- 先只读看板（MVP-4），后拖拽编辑器（MVP-5）。

## 六、分阶段（权威版见 `docs/04` §六）

| MVP | 名称 | 质变点 |
|---|---|---|
| 1 | 单链脚本验证 | 打通「角色=provider+persona」 |
| 2 | **自研 StateGraph 引擎** | 工作流可配置（图 DSL + 循环） |
| 3 | 状态+交接+消息+恢复 | 可持久化/可恢复/分账/防死锁 |
| 4 | 只读激活看板 | 状态可视化 |
| 5 | 角色导入+画布连边 | 零代码自定义团队（G6） |
| 6 | 打磨 | 生产可用 |

**质变点 = MVP-2（自研 StateGraph）**。MVP-1 用 workflowEngine 临时验证，从"一堆 skill"到"编排工具"的跨越在 MVP-2。

**质量验证双层模型**：
- **结构覆盖**（验证工作流被完整执行：允许工具被调用、委托义务被履行、限制工具被拒绝）——StateGraph 的路由/条件边/熔断都是**纯函数**，用 **BDD + mock 隔离 LLM 做确定性测试（零 Token、毫秒级）**，**提前到 MVP-2**（不等 MVP-6 全套门禁）。
- **语义评估**（判断输出质量）——LLM-judge，落到 MVP-6 对抗评审。

## 七、决策点状态（已收敛）

| 决策点 | 结论 |
|---|---|
| 编排引擎 | ✅ 自研 StateGraph（非 workflowEngine script） |
| 运行时底座 | ✅ 分层复用：subagents(执行)+自建(引擎/角色/画布)；不依赖 experimental agentTeams |
| 角色定义 | ✅ YAML 元数据 + `system_prompt_ref`（Prompt 来自 skill） |
| 开发路径 | ✅ 纯 Host CLI 先行（MVP-1/2 不碰 UI） |
| 编排 vs 可视化顺序 | ✅ 编排（MVP-2）前置于可视化（MVP-4） |

## 八、风险

| 风险 | 缓解 |
|---|---|
| StateGraph 自研复杂度 | 参考 dsh-state-graph 逻辑不抄码；MVP-2 只做 seq+cond+loop |
| 冷恢复延迟 | 生命周期 resident/on-demand/hybrid + 活跃窗口 + SLA>10s 降级人工 |
| 循环失控 / 成本爆炸 | 迭代熔断(25) + 硬 Token 预算 + 人工审批节点（未控 Agent 循环可达月 $10K 级 ⚠️） |
| 记忆/上下文膨胀 | handoff 精简 + art:// 引用 + 滑动窗口摘要；实证：动态上下文剪枝 -85%、长序列压缩 -80%、图结构压缩 -78.9% 🧪；**第一步=art:// 工件引用（MVP-2 artifacts 引用存储），非上下文摘要** |
| 工作区卫生退化 | 每角色独立产出目录 + 卫生检查 |
| Agent 治理缺失 | 将 Agent 视为"特权内部人员"：短期凭证 + 记忆防投毒 + 执行前验证；L3 `tools`=最小权限声明，L5 引擎侧只允许调用角色声明工具 |
| 可观测性不足无法调试 | OpenTelemetry 逐节点插桩，trace_id 贯穿全链 |
| 回归测试成本高 | SPRT 节省 78% 试验；trace-first 离线分析 100% 成本节省 🧪 |
