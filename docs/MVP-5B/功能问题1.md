## 一、【P0 最重要】主 agent 不执行 weave 图

### 1.1 症状还原（用户实测）

```
用户：用 weave 创建一个简单的 TODO 网页工具
  ↓
主 agent 思考：用户第三次发送同样的消息，我需要直接用 weave_run_chain...
  ↓
工具调用：weave_run_chain · 创建一个简单的 TODO 管理网页应用
  ↓
chain 执行被中止
  ↓
主 agent 反复折腾：job_list / 读日志 / weave_propose_task（最后才调）
```

**核心症状**：主 agent 首选 `weave_run_chain`，**从未主动调 `weave_propose_task`**。等到折腾不动了才调一次，但已经浪费 5+ 轮。

### 1.2 根因（三层）

#### 根因 A：`weave_run_chain` 未废弃

`src/index.ts` 的 `apply` 里还在注册：

```ts
registerChainTool(ctx)   // ← MVP-1 遗留，未移除
```

**问题**：工具列表中 `weave_run_chain` 存在，且描述看起来很"能干活"（"执行 MVP-1 单链..."），主 agent 的 LLM 看到就优先调它。

#### 根因 B：`weave_graph_help` 缺"任务入口契约"章节

规划 MVP-5 §4.3 明确要求：

```markdown
## 任务入口契约
### 何时调 weave_propose_task
用户说"用 weave 创建 XXX"时：调 weave_propose_task，不要直接调 weave_run_graph。
```

**实际 `src/cli/graph-commands.ts` 的 `weave_graph_help` 里没有这一章节**——只有"暂停处理契约"。主 agent 得不到"用户说创建 XXX → 调 propose_task"的明确指引。

#### 根因 C：`weave_propose_task` 描述不够强

`src/cli/propose-commands.ts` 的 description：

```
创建 weave 任务草稿并打开右侧编辑面板。**不直接执行图**。
用于用户说"用 weave 创建/编排 XXX"时。
```

**问题**：
- 没有"**必须**"级别的措辞
- 没提"**禁止用 weave_run_chain**"
- 没提"**禁止直接 weave_run_graph**"

### 1.3 修复（三层，全做完才闭环）

#### 修复 A：移除 `weave_run_chain`（推荐）

```ts
// src/index.ts
export function apply(ctx: Context, config: Config = {}): void {
  // ...
  registerGraphCommands(ctx)
  registerVisualCommands(ctx)
  registerGraphRunCommand(ctx, { rolesDir })
  registerGraphResumeCommand(ctx)
  registerProposeCommand(ctx)
  // ★ 删除：registerChainTool(ctx)
  // ...
}
```

同时删除 `src/cli/chain-tool.ts` 的注册（或整个文件移到 `_deprecated/`）。

**验证**：主 agent 工具列表里不再有 `weave_run_chain`。

#### 修复 B：`weave_graph_help` 补"任务入口契约"

在 `src/cli/graph-commands.ts` 的 help 字符串里，**在"暂停处理契约"之前**插入：

```
## 任务入口契约（主 agent 必读）

### 何时调 weave_propose_task（首选，绝大多数场景）

用户说以下任意一句时：
  · "用 weave 创建 X"
  · "用 weave 编排 X"
  · "用 weave 做 X"
  · "打开 weave 面板"
  · "帮我生成 XXX 项目"

→ **必须调用 `weave_propose_task`**

流程：
  weave_propose_task → 面板自动打开 → 用户编辑 → 用户点【开始工作】→ 图执行

调用后主 agent 行为：
  1. 向用户报告"已创建任务草稿，面板已打开"
  2. **不要**等图跑完才回复（图还没开始跑）
  3. **不要**替用户点【开始工作】
  4. 用户点【开始工作】后，引擎自动执行，主 agent 不需要额外动作

### 何时才调 weave_run_graph（极少数场景）

**只在**以下情况：
  · 用户明确说"跳过编辑，直接跑"
  · 前几轮对话已给出图 YAML 绝对路径 + 完整需求 + 明确"直接执行"

### ❌ 禁止

- **禁止调 `weave_run_chain`**（已废弃，会中止）
- **禁止**在用户没有明确说"跳过编辑"时直接调 `weave_run_graph`
- **禁止**反复调 `weave_propose_task` 尝试不同模板（会触发单图模式守卫）
```

#### 修复 C：`weave_propose_task` 描述增强

```ts
// src/cli/propose-commands.ts
description:
  '【首选工具】当用户说"用 weave 创建/编排/做 XXX"时，**必须调用此工具**。' +
  '创建一个任务草稿并打开右侧编辑面板，用户编辑后点【开始工作】才执行图。' +
  '调用后请向用户报告"面板已打开，请编辑后点【开始工作】"，然后停止等待。' +
  '**禁止**用 weave_run_chain（已废弃）或 weave_run_graph（跳过编辑）替代。' +
  '**禁止**在会话已有活跃任务时再次调用（会返回错误提示）。',
```

#### 修复 D（加固）：单图守卫返回引导

`propose-commands.ts` 的 `execute` 里，当单图守卫拒绝时，不只是返回错误，还要引导：

```ts
if (!guard.ok && guard.existing) {
  return [
    `❌ 已有活跃任务（${existing.taskId}，状态：${existing.status}）。`,
    '',
    '请选择一个操作：',
    '  1. 等用户完成当前任务',
    '  2. 调用 POST /api/weave/tasks/:taskId/cancel 取消当前任务',
    '  3. 若用户想开新任务，先取消当前任务',
    '',
    '**不要**尝试不同模板重复调用 weave_propose_task。',
  ].join('\n')
}
```

### 1.4 验证清单（P0 做完后必测）

| # | 场景 | 期望 |
|---|---|---|
| 1 | 用户说"用 weave 创建 TODO 工具" | 主 agent 调 `weave_propose_task`（**不是** chain） |
| 2 | 工具列表 | 无 `weave_run_chain` |

## 二、【P0】`/api/weave/tools` 返回错内容

### 2.1 症状

用户看到的工具白名单：

```
weave_graph_help
weave_graph_report
weave_graph_resume
weave_graph_show
weave_graph_status
weave_graph_tail
weave_graph_validate
weave_graph_watch
weave_propose_task
weave_run_chain
weave_run_graph
```

**这些是主 agent 视角的 CLI 工具，不是角色（subagent）可用工具。**

### 2.2 根因

`src/l4-visual/host/routes.ts` 的 `/tools` 端点用了：

```ts
json(res, 200, { tools: ctx.tools.list() })  // ← ctx.tools 是主 agent 工具表
```

**角色能用的工具**是 subagent 的 `toolFilter` 白名单——另一套。

### 2.3 修复

```ts
// src/l4-visual/host/routes.ts
/** 角色可用的工具白名单（subagent toolFilter 的候选） */
const SUBAGENT_TOOLS = [
  { id: 'read',              label: '读取文件',   desc: '读取工作区文件内容' },
  { id: 'glob',              label: '文件搜索',   desc: '按 glob 模式搜索文件' },
  { id: 'grep',              label: '内容搜索',   desc: '按正则搜索文件内容' },
  { id: 'write',             label: '写入文件',   desc: '创建/覆盖文件' },
  { id: 'edit',              label: '编辑文件',   desc: '修改已有文件' },
  { id: 'pwsh',              label: '执行命令',   desc: '运行 shell 命令' },
  { id: 'ask_user_question', label: '询问用户',   desc: '向用户提问' },
]

if (rest === '/tools') {
  if (method !== 'GET') { json(res, 405, { error: 'method not allowed' }); return }
  json(res, 200, { tools: SUBAGENT_TOOLS })
  return
}
```

### 2.4 前端同步改造

`RoleEditor.tsx`：

```tsx
// 之前（假设）：availableTools.map(t => ... {t})  显示裸 id
// 之后：
{availableTools.map((t) => {
  const on = form.tools.includes(t.id)
  return (
    <button
      key={t.id}
      title={t.desc}
      className={`chip ${on ? 'on' : 'off'}`}
      onClick={() => set({

      {on ? '✓ ' : ''}{t.label} <code>{t.id}</code>

  )

```

显示效果："读取文件 `read`"而不是裸 `read`。

## 三、【P1】`/api/weave/providers` 与环境不一致

### 3.1 根因

前端 `RoleEditor` 调 `/providers`，走三级探测：
- **dynamic**：`ctx.subagents.list()` —— 真实
- **yaml-scan**：扫 `roles/*.yaml` —— 历史
- **static**：写死 —— **假数据**

用户看到的可能是 yaml-scan 或 static 的兜底数据，**与运行时实际 provider 不符**。

### 3.2 修复

#### 后端 `/providers` 增加 source 字段

```ts
// routes.ts
if (rest === '/providers') {
  const result = listProviders(ctx)   // 返回 { providers, source }
  const warning = result.source !== 'dynamic'
    ? `Provider 列表来源：${result.source}（非实时探测），实际可用 provider 以 DSH 环境为准`
    : undefined
  json(res, 200, { ...result, warning })
  return
}
```

#### 前端提示

```tsx
{providerSource !== 'dynamic' && (
  <div className="warn-banner">
    ⚠ {providerWarning}
  </div>
)}
```

#### 更激进：降级时直接空列表

```ts
if (result.source !== 'dynamic') {
  json(res, 200, {
    providers: [],
    source: result.source,
    warning: '无法获取运行时 provider 列表，请检查 DSH 环境',
  })
  return
}
```

前端：provider 空 + 警告 → **禁用"创建"按钮**。

## 四、【P1】角色编辑默认值太多 + 高级区折叠

### 4.1 新建角色预填合理默认

```ts
// src/client/state/board-state.ts
export const PLATFORM_DEFAULTS = {
  capabilities: ['read'],
  tools: ['read', 'glob', 'grep'],
  readable: ['inputs/**', 'productions/**'],
  produces: [{ kind: 'doc', name: 'output.md', contract: '' }],
  forbidExtensions: ['.py', '.js', '.ts'],
  onlyMarkdown: true,
}
```

`RoleEditor` 的 `BLANK`：

```ts
const BLANK: RoleFormData = {
  id: '', name: '', description: '', order: 10, tags: '',
  provider: '', model: '',
  ...PLATFORM_DEFAULTS,   // ★ 从这里取默认
  consumes: [], suggestsNext: [], forbidden: '', requiredSections: '',
}
```

### 4.2 编辑器分区（基础默认展开，高级默认折叠）

```
┌─ 角色编辑器 ──────────────────────┐
│ [基础]  ← 默认展开                  │
│   ID / 名称 / 描述 / 排序 / 标签    │
│   Provider / 模型（默认值已选）      │
│   能力集（默认 read）               │
│                                    │
│ [高级] ▸ ← 默认折叠                 │
│   工具白名单                        │
│   可读范围                          │
│   产出/消费/推荐下一步               │
│   输出约束 / 非职责                  │
│   SKILL.md 预览                     │
└────────────────────────────────────┘
```

**用户 80% 场景只改基础区**，高级区默认值可直接用。

### 4.3 capabilities 视觉区分

```tsx
<button
  className={`chip ${on ? 'on' : 'off'}`}
  onClick={...}
>
  {on ? '✓ ' : ''}{c.label}
</button>
```

```css
.chip.off {
  opacity: 0.55;
  border-style: dashed;
}
```

**含义**：
- `chip.on`（实心）= 角色已有该能力
- `chip.off`（虚线）= 平台支持但角色未启用，可勾选

## 五、【P2】SKILL.md 展示

### 5.1 后端加 API

```ts
// routes.ts
if (rest.match(/^\/roles\/[^/]+\/skill$/)) {
  const roleId = rest.split('/')[2]
  const skillPath = join(skillsDir, roleId, 'SKILL.md')
  if (!existsSync(skillPath)) {
    json(res, 404, { error: 'skill not found' })
    return
  }
  json(res, 200, { content: readFileSync(skillPath, 'utf8') })
  return
}
```

### 5.2 前端只读展示

```tsx
<div className="re-section">
  <h4>技能提示词（SKILL.md）</h4>
  <div className="skill-hint">
    （此内容为角色的系统提示词，如需修改请在对话中让主 agent 编辑
    <code>skills/{roleId}/SKILL.md</code>）
  </div>
  <pre className="skill-preview">{skillContent}</pre>
</div>
```

**为什么只读**：SKILL.md 是 prompt，直接编辑风险高（可能破坏角色职责边界）。修改走主 agent 更安全。

## 八、修复后的完整时序

```
用户：用 weave 创建一个 TODO 网页工具
  ↓
主 agent：调 weave_propose_task（help 契约 + 描述引导）
  ↓
面板自动打开 + taskId=task-xxx
  ↓
主 agent 回复："已创建任务草稿，面板已打开，请编辑后点【开始工作】"
  ↓ （主 agent 停止，等用户操作）
用户编辑（改模板/加角色/配门禁）
  ↓
用户点【开始工作】（面板调 weave_run_graph）
  ↓
图执行 → 节点依次跑
  ↓
主 agent 不插嘴（SSE 事件驱动前端看板刷新）
  ↓
图完成 → 前端展示产物 + 交接单
```

**不再出现**：
- ❌ 主 agent 调 `weave_run_chain` 卡住
- ❌ 反复创建草稿（守卫拒绝）
- ❌ 主 agent 不知道新流程
- ❌ 工具白名单显示错内容
